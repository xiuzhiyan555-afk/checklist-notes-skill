# 平台安装参考

> [!info] 从这里开始
> 先安装给 AI 读取的方法，再启用 Obsidian 的显示样式。==完成两步==，才同时具备整理能力和配套外观。

## 一、准备好这三样

1. **软件：** 一款支持本地 Skill 的 AI 工具，以及已经安装并建库的 Obsidian。本说明覆盖 WorkBuddy 桌面端、Codex 本地端、Claude Code 本地端。
2. **资料：** 本交付包和一篇准备整理的材料；首次测试可直接使用包内[样例笔记](../assets/样例笔记.md)。
3. **位置：** 先确认自己的 Obsidian 库文件夹。AI 需要能读取材料，并获得向你指定文件夹写入的权限；仅安装 Skill 不会自动获得==文件权限==。

## 二、解压后认清文件

| 文件或文件夹 | 用来做什么 | 是否需要改名 |
| --- | --- | --- |
| 清单体笔记Skill.md | 人阅读的使用入口 | 可以，不影响 AI 方法 |
| checklist-notes 文件夹 | 完整 AI 方法及所需资源 | 保留文件夹名 |
| checklist-notes-skill-v0.3.zip | 供 WorkBuddy 上传的纯技能包 | 不用再次压缩 |

1. **复制完整：** `checklist-notes` 内必须有 `SKILL.md`、`assets`、`references`、`agents`；不能只复制 `SKILL.md`。
2. **名称区别：** 中文展示名是“清单体笔记Skill”，技术调用名是 `checklist-notes`。有的工具只显示英文名称，两者对应同一个技能。

## 三、安装到 AI 工具

按正在使用的工具选一条路线，不用全部安装。

1. **WorkBuddy：** 在“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”中，选择交付包里的 `checklist-notes-skill-v0.3.zip`；导入后在“已安装”中确认已启用。上传的是==纯技能包==，不要上传包含外层说明的整个交付包。[官方步骤](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)
2. **Codex：** 将完整 `checklist-notes` 文件夹放到个人技能目录 `.agents/skills/` 下；确认最终有 `.agents/skills/checklist-notes/SKILL.md`。未识别时重启本地端，再在技能选择中查找或使用 `$checklist-notes`。[官方步骤](https://learn.chatgpt.com/docs/build-skills)
3. **Claude Code：** 将完整文件夹放到个人目录 `.claude/skills/` 下；确认最终有 `.claude/skills/checklist-notes/SKILL.md`。在本地会话输入 `/checklist-notes` 调用。[官方步骤](https://code.claude.com/docs/en/skills)

| 工具 | macOS／Linux 的完整目标目录 | Windows 的完整目标目录 |
| --- | --- | --- |
| Codex | `~/.agents/skills/checklist-notes/` | `%USERPROFILE%\.agents\skills\checklist-notes\` |
| Claude Code | `~/.claude/skills/checklist-notes/` | `%USERPROFILE%\.claude\skills\checklist-notes\` |

4. **找到个人目录：** macOS 在访达按 `Command+Shift+G` 输入 `~` 回到个人目录，再按 `Command+Shift+.` 显示隐藏文件；Windows 在资源管理器地址栏输入 `%USERPROFILE%`；Linux 打开个人目录并显示隐藏文件。然后按上表逐级进入或新建 `.agents/skills`、`.claude/skills`，把完整技能文件夹放进去。已有同名技能先比较，保留旧版备份。
5. **没有本地安装功能：** 可把完整技能文件夹交给能够读取本地文件的 AI，让它从 `SKILL.md` 开始读取引用资源；这是手动加载，不等于已经安装。纯网页聊天若不能访问本地文件，只能接收材料并返回 Markdown，再由你保存。

## 四、启用 Obsidian 样式

1. **打开目标位置：** 在你实际使用的笔记库中，进入“设置 → 外观 → CSS 代码片段”，点击文件夹图标。==以软件打开的位置为准==，避免复制到另一座库。
2. **复制样式：** 从技能文件夹的 `assets` 中复制 `checklist-notes.css` 到刚打开的文件夹；同名文件先比较，不覆盖不明版本。
3. **启用开关：** 回到代码片段设置，刷新列表，打开 `checklist-notes` 的开关。如果开关已开但样例仍是默认颜色，刷新后关闭再开启一次，再回笔记复查。常见默认位置是该库的 `.obsidian/snippets/`。[官方步骤](https://obsidian.md/help/snippets)
4. **放入样例：** 将 `assets/样例笔记.md` 复制到库内，使用 Obsidian 打开。样例已带所需属性；后续生成的笔记也要保留以下属性。

```yaml
---
cssclasses:
  - checklist-notes
---
```

5. **作用范围：** 样式只影响带此类名的笔记。入口页另带 `checklist-cover` 以收起属性区，方便截图；普通笔记不需要此类名。没有 CSS 或没有属性时，结构仍可读，但无法获得配套颜色。

## 五、做一次最小测试

1. **确认加载：** 请 AI 读取或调用 `checklist-notes`，简要说明何时用表格、如何选重点，并指出它读取的入口与配套 CSS。只复述名字不能证明加载成功。
2. **提供材料：** 发送下面的调用文字，并填入你自己的目标位置。AI 无权访问目标位置时，先由它输出 Markdown，再手动保存。

> [!info] 可直接复制
> 使用清单体笔记Skill整理下面材料。先忠实保留主次、条件和因果；适合对照时用表格；主动筛选绿色加粗的短语重点。输出带 checklist-notes 属性的 Markdown，保存到我指定的文件夹；材料中的未解问题保留为待确认。
> **目标位置：** 你的笔记库与文件夹。
> **材料：** 我们有三份操作说明。A 用于新员工，B 用于主管复核，C 用于临时替岗。三份都要保留原始出处、适用条件和负责人；整理后先请负责人核对，版本冲突暂不自行合并。

3. **核对结果：** 原文的三种用途应清楚保留；若用表格，应能对照“资料—用途”，不能编造负责人姓名。重点应是关键条件或行动短语，不能把 A、B、C 全部染绿。
4. **核对显示：** 用相同窗口宽度和缩放，分别切换阅读模式、实时预览；把光标移出正在编辑的段落或表格后再比较。

| 检查项 | 通过时应看到什么 | 未通过先检查什么 |
| --- | --- | --- |
| 层级 | 金黄标题、橙色主项、淡暖子项、灰色明细 | CSS 开关和笔记属性 |
| 重点 | 仅关键短语绿色加粗，表内短标签不染绿 | 是否使用高亮语法，是否混用旧样式 |
| 列表与表格 | 自动序号正常，表格可编辑且关系清楚 | 是否为原生 Markdown，是否有复杂嵌套 |
| 正文与文件名 | 正常字重，文件名不误变绿色斜体 | 文件名是否用行内代码或安全链接 |
| 换行 | 无正文溢出，尽量没有一两字尾行 | 字体、有效宽度及句子是否冗长 |

## 六、出现差异怎么处理

1. **先分模式：** 阅读模式隐藏语法，实时预览在光标进入时显示语法，源码模式显示全部语法；这部分不隐藏。[官方说明](https://obsidian.md/help/edit-and-read)
2. **再查冲突：** 先用样例测试，确认只带 `checklist-notes` 类；若仍异常，在临时测试库使用默认主题和本 CSS 对照。不要为排错擅自改动正式库的其他配置。
3. **表格过长：** 减少无用列，把长解释放回清单；不使用合并单元格或表内多层列表来勉强排版。
4. **尾行过短：** 先删冗余，再调整合理阅读宽度；==保留关键条件==，不通过手动换行或整行禁止换行凑版。
5. **仍有问题：** 向维护者提供 Obsidian 版本、系统、主题、启用片段、匿名化样例和同宽双模式截图。只能检查文件时，明确记录“尚未完成界面验收”。

> [!info] 支持范围
> 本包自带 CSS，无社区插件与外部网络服务依赖。字体、窗口、主题、编辑器控件仍可能带来差异；本机检查不等于所有外部环境已验证。Skill 格式与安装文档可检查，WorkBuddy 上传后的平台识别仍以实际导入结果为准。
