# 安装与验收：给 Agent 执行

用户只需提供完整安装包（或其下载链接）和目标 Obsidian 库的路径，说明“安装并验收清单体笔记 Skill”。**安装成功的定义是：AI 能调用方法，目标库 CSS 已启用，样例笔记在阅读模式和实时预览中显示正确。**下载或复制文件不算安装完成。

## Agent 执行顺序

1. **定位：** 解压完整包，确认 `checklist-notes/SKILL.md`、`assets/checklist-notes.css`、`assets/样例笔记.md`、`scripts/install_obsidian.py` 均存在。确认用户指定的实际 Obsidian 库中有 `.obsidian/`。如果用户只给了链接，自行下载和解压；网络或文件权限受限时仅报告具体缺口。
2. **安装 Skill：** 在当前 Agent 的 Skill 机制中导入完整的 `checklist-notes` 文件夹。WorkBuddy 可优先导入内层 `checklist-notes-skill-v0.6.zip`；若有可操作的上传界面，由 Agent 完成。安装后实际读取 `SKILL.md`，确认表格与重点规则可以被调用。只把目录复制到任意位置不算已安装。
3. **安装 CSS：** 对用户指定的那个库运行 `python3 checklist-notes/scripts/install_obsidian.py --vault "目标库绝对路径"`。脚本只处理该库的 `checklist-notes.css`、`appearance.json` 的 `enabledCssSnippets` 列表，以及一篇不覆盖原文件的样例；遇到不同旧文件会先备份。若系统没有 Python 3，Agent 按脚本同样逻辑手动完成并核对结果，不把此操作交给用户。
4. **确认笔记属性：** 打开样例，检查开头包含 `cssclasses: [checklist-notes]`。后续新笔记必须带这一属性；旧笔记要应用样式时，先保留其原有属性和内容，再追加此类名。
5. **界面验收：** 在同一 Obsidian 窗口宽度，分别检查阅读模式和实时预览。样例应有蓝色说明框、粉色链接、金黄标题、橙色一级标签、淡暖二级标签、灰色三级标签、绿色短语重点、正常列表标记和有留白的表格；表格第一列的行名也应在两种模式中呈橙色。先在同一有效内容宽度检查一级数字、二级字母、三级罗马的缩进和表格列宽，再移开光标检查颜色与行距；分别记录阅读与实时预览的结果。上述颜色以 Obsidian 默认主题（无第三方主题）为基准；第三方主题可能导致个别颜色或表格被覆盖，遇到时按"哪一步不对"表处理。源码模式露出 Markdown 符号是正常的，不作为实时预览通过证据。
6. **内容验收：** 用样例或用户给的短材料实际调用 Skill，检查结构标签、表格使用条件、绿色重点和 `cssclasses`。仅复述 Skill 名字不能证明已调用。
7. **报告：** 分别写明 Skill 识别、CSS 文件、CSS 开关、样例双模式、真实调用五项的通过状态和证据。任何一项未查到都标"未验证"，不得报"全部安装完成"。报告时主动向用户转述主题兼容性说明（本样式基于 Obsidian 默认主题设计验收，其他主题可能不完全兼容，可切回默认或由 AI 在当前主题上针对性调整），不要等用户追问。

## 哪一步不对，Agent 怎么处理

| 现象 | 先检查 | 修复与复验 |
| --- | --- | --- |
| Skill 无法调用 | 是否上传内层纯技能包；文件夹根目录是否有 `SKILL.md`；平台是否需要刷新 | 重新导入或刷新，再实际读取规则；平台不支持自动导入时说明唯一需要用户完成的上传动作 |
| 样例全是默认颜色 | 目标库是否选对、`appearance.json` 是否启用片段、样例是否带类名 | 重新运行安装脚本，刷新 Obsidian 片段列表并复验；不得改另一个库 |
| 有些颜色不对 | 是否混用了旧 `cssclasses`、旧片段或第三方主题规则 | 在同库新建仅带 `checklist-notes` 类的样例对照；本样式以 Obsidian 默认主题为基准，第三方主题（如 Blue Topaz）覆盖导致的偏差，优先请用户切回默认主题核对，或只针对该主题的冲突选择器做最小修复，不全局关掉其他样式 |
| 阅读与实时预览不同 | 是否同宽、同缩放；光标是否正在编辑；表格是否为实时预览组件 | 先排除编辑中的语法显示，再修订 CSS 对两种模式的选择器，逐项复验 |
| 列表消失或表格拥挤 | Markdown 是否使用原生列表/表格，CSS 是否影响 `display` 或缩进 | 保留原生语法并修 CSS；不手打序号、不把长解释硬塞表格 |
| 只有最后一两个字换行 | 内容是否冗长、库有效宽度是否与样例不同 | 优先删冗语、调整表述；保留条件，不强制不换行 |

## 安全与边界

只修改用户指定的库和本 Skill 的文件。脚本会备份被替换的同名 CSS 与修改前的外观配置，不覆盖已有样例。若无法操作 WorkBuddy 上传界面或无法查看 Obsidian 界面，明确指出未完成的那一步，不把文件检查等同于视觉验收。不要要求用户自行寻找 CSS 目录、逐项改设置；确需用户点击权限或上传时，只说明当下唯一动作。
