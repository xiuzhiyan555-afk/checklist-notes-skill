# 清单体笔记Skill

先服务内容关系，再服务视觉呈现。交付可扫读、可追溯的笔记，不把格式完整当作理解完整。

## 一、处理顺序

1. **读取输入：** 读完整材料和用户用途；从现有上下文确定输出位置。缺失材料、用途会改变结构时才询问。
2. **确认关系：** 找出核心结论、目标、包含关系和因果顺序。将用途归于目标、例子归于观点、条件归于判断。同层只放同类信息。
3. **选择主线：** 按材料选择主线：经历可按过程，方案可按背景—目标—关键方案，研究可按问题—依据—已有判断—未解问题。只是选择依据，不固定套章，不补齐原文没有的结论。
4. **保留事实：** 删除口述重复，保留关键条件、事实、分歧与未解问题。明确来源观点、用户表达和 AI 建议；不得冒写用户的洞察、决策或亲身经历。
5. **控制层级：** 用最少层级组织内容，再按下列规则决定表格与重点。口播成稿、原始逐字稿和思考现场只在用户要求时另做整理版，保留原始材料入口。

## 二、标题与清单

- 章节标题简短，如“背景”“目标”“具体怎么做”；解释放在标题下，不写“背景：一整句解释”。
- 每条用 `**关键词：** 正文`；关键词概括原有含义，不能为了凑标签拆散内容。粗体结束后保留空格。
- 有先后用有序列表，并列用无序列表。使用原生 Markdown 列表，不手打 a、i、圈号或表情充当列表。
- 一级章节以下通常只需一至两层列表；只有独立明细才增加第三层。禁止每点固定拆成四五个子项。
- 默认各层保留原生数字或圆点；用缩进与标签色辨别层级。不用 CSS 伪造跨行计数来追求 1/a/i 外观。

## 三、何时使用表格

先判断阅读任务：读者是否需要横向比较，或沿同一行查找对应关系？

- 满足“至少两项可比内容 + 至少两列有意义的字段（对象名与一个对应字段也算）”，并且表格能比清单更快显示关系时使用。包括方案对比、步骤与做法对应、阶段与产出对应、人群与建议对应。
- 优先 2—4 列，每行一个对象，每列一种信息。列名由原文确定；不为凑列发明产出、原因、状态或验收结果。空缺用“未提供”，不能脑补。
- 同一组放一张整合表；不要每个模块重复建表。已有正文转表后移走重复表达，必要解释留表外。
- 只有一个观点、需要连续解释因果或故事、各项没有共同维度、单元格需要多层嵌套时，用清单或段落。
- 长解释移出表格并建立明确对应；不能通过删关键条件凑短。表格太宽先减少非必要列，无法简化则改为分组清单。
- 默认普通 Markdown 表格，不合并单元格，不用 HTML 表格、单元格嵌套列表或手工编号。多个独立动作可拆成多行，并重复所属对象，保持一张表。
- 表内短标签、阶段名、列头已有定位作用，不加绿色；已有关键条件或判断短语可按重点规则标记。

## 四、绿色重点怎么选

结构标签负责导航，绿色加粗负责提醒读者记住什么。两者分开。

1. 优先选原文已成立的核心判断、决定结果的条件或限制、容易误解的关键差异、关键行动词或数字；一般选 2—12 个汉字，必要时稍长，以保留完整含义。
2. 原则上每个有实质内容的段落组有重点；连续约三个实质段落或清单主项至少检查到一处重点，避免开头密集、后文全无。短章节通常 1 处，较长章节 1—3 处；这是分布检查，不是机械配额。
3. 每段或主项通常不超过一处，通常不超过正文的约 15%；不整句、整段或整行标绿。若没有值得强调的内容，保留不标，不能为均匀添加或改变观点。
4. 不标章节标题、行首结构关键词、表头、表内短标签、泛词、重复结论。数字只在它承载关键证据或阈值时标，不因醒目就选。
5. 使用 `==关键短语==`，配套 CSS 自动显示绿色加粗；不要再包一层 `**`，不要使用斜体代替重点。除行首结构标签外，默认也用这一语法表达内容强调，避免普通粗体与标签色混淆。
6. 选中重点后反读：只看标记能否抓住文章主要意思？把它放回原句是否保留了否定、前提、归属与不确定性？若“不是必须”只标成“必须”，必须修正。
7. 如用户追问，能说明每处标记属于核心判断、关键条件、差异或行动，不将“我觉得重要”作为唯一依据。

## 五、Obsidian 输出

用户请求安装时读取 [安装指引](references/安装与兼容.md) 并代为执行。日常整理无需重复安装，样式文件为 [checklist-notes.css](assets/checklist-notes.css)，格式样例为 [样例笔记](assets/样例笔记.md)。

- 目标笔记的属性包含 `cssclasses: [checklist-notes]`；更新已有笔记时保留其他属性，但如存在冲突旧样式，先报告并只在授权范围处理。
- 默认新笔记只用这一独立类，不依赖其他库、私人文档、主题插件或本机绝对路径。
- 文件名含下划线时使用安全链接或行内代码，禁止让文件名参与强调解析。
- 跨平台无 CSS 时保留结构，说明绿色样式只在支持的环境生效；用户要求通用 Markdown 时将重点降级为 `**关键短语**`。
- 除用户已授权安装外，只交付 CSS 和启用说明，不自动改变整库设置或替换已有样式。

## 六、交付核对

- 内容：原来主要观点、包含关系、关键条件仍在；没有发明分类、用户想法或验证结果。
- 表格：每列都服务一个真实的比较或对应任务；正文无重复堆积；复杂内容已回清单。
- 重点：短语可解释，分布合理；没有整句染色或把标题重复标绿。
- 文件：来源入口可用，列表与表格语法正确；只有目标笔记使用样式。
- 显示：具备界面访问时，在相同有效内容宽度检查阅读与实时预览，移开光标后再比较。不能把文件语法通过当作视觉验收。没有界面访问时明确“未做双模式视觉验收”。

当前能力是已有材料的整理与呈现，不承诺代替用户完成内化或形成经过验证的模型。后续按真实失败样例修订。
